# CLAUDE.md — GRASS-AUTO-DETAIL

Этот файл даёт Claude контекст по проекту. Читай его в начале каждой сессии.

## Что это за сайт

**autodetail.ge** — каталог автохимии компании **BBS / Biko Ltd**, Батуми, Грузия.
Сайт позволяет клиентам просматривать товары, фильтровать по бренду и категории,
добавлять в корзину и оформлять заказ через форму (EmailJS).

AutoDetail — самостоятельное направление BBS, не подпапка Grass.
Grass — это HoReCa химия. AutoDetail — отдельный бизнес с брендами Detail и GraSS.

## Товары и бренды

- **Detail** — профессиональная автохимия (артикулы вида `DT-XXXX`)
- **GraSS** — автохимия и аксессуары (артикулы вида 6-значных чисел)
- **Всего ~173 товара**, хранятся в виде JSON-массива внутри `index.html`
- Поля товара: `brand`, `ge` (название гру), `ru` (название рус),
  `dge` (описание гру), `dru` (описание рус), `art`, `pkg`, `price`, `cat`

## Текущая структура проекта

```
GRASS-AUTO-DETAIL/
├── index.html   ← весь сайт: HTML, CSS (~1000+ строк), JS, данные товаров
├── CNAME        ← привязка домена autodetail.ge к GitHub Pages
├── .gitignore
└── img/         ← ~170 изображений товаров
    ├── DT-XXXX.jpg   ← товары Detail
    └── XXXXXX.jpg    ← товары GraSS
```

## Что находится внутри index.html

- Вся вёрстка и стили (inline CSS, ~1000+ строк)
- Логика фильтрации по бренду и категории
- Двуязычность: грузинский / русский (переключатель в шапке)
- Корзина (боковой drawer)
- Форма заказа с отправкой через EmailJS
- JSON-массив с данными всех ~173 товаров

## Ограничения — что нельзя делать без отдельного разрешения

- **Не выносить товары** в `data/products.json` — пока данные остаются в `index.html`
- **Не переименовывать и не перемещать** изображения из `img/` —
  имена файлов привязаны к артикулам товаров в коде
- **Не создавать папки** `css/`, `js/`, `data/` или другие
- **Не делать рефакторинг** попутно с другими задачами
- **Не менять настройки EmailJS** без отдельного разрешения

## Правила работы с этим репозиторием

1. **Не ломать рабочий сайт.** `autodetail.ge` живёт на GitHub Pages — любое изменение
   `index.html` или `CNAME` сразу отражается на продакшне.
2. **Маленькие шаги.** Каждое изменение — отдельный коммит с понятным сообщением.
3. **Сначала план, потом код.** Перед любым изменением кода объяснить что и зачем,
   дождаться подтверждения пользователя.
4. **Не коммитить без явного подтверждения** от пользователя.
5. **Не создавать файлы и папки** без явного запроса.
6. **После изменений в коде** обязательно проверить, что сайт открывается
   и визуально не сломан.
